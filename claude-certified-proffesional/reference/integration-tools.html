Tool design (anti capability bloat)

Writing tools for agents · Define tools · Context engineering

  • Minimal viable set. If a human can't say which tool to use, the agent can't either. Least privilege = remove unneeded tools.
  • Consolidate workflows: schedule_event instead of list_users + list_events + create_event; search_logs instead of read_logs; one tool with an action parameter.
  • Namespace: asana_search, jira_search, github_list_prs. Matters even more with tool search.
  • Descriptions are "by far the most important factor". At least 3–4 sentences: what, when (and when not), parameters, limits. Unambiguous parameter names (user_id).
  • Responses: high-signal fields and meaningful identifiers, not opaque internal references. response_format concise/detailed (concise ≈ ⅓ the tokens). Paginate, filter, truncate. Claude Code caps tool output at 25k tokens by default. Errors should say how to fix the call.
  • input_examples for complex inputs (72% → 90% accuracy on complex parameters); ~20–200 tokens each. Advanced tool use · Define tools

MCP authorization essentials

Authorization · Client registration · Security considerations

ScopeOptional; for HTTP transports. stdio servers get credentials from the environment.
RolesMCP server = OAuth 2.1 resource server; MCP client = OAuth client; separate authorization server.
Discovery401 + WWW-Authenticate (with resource_metadata and ideally scope) → Protected Resource Metadata (RFC 9728) → authorization server metadata (RFC 8414 / OIDC).
Registration order1 pre-registration · 2 Client ID Metadata Document (HTTPS URL as client_id; AS fetches the JSON and validates redirect_uris) · 3 Dynamic Client Registration as fallback (deprecated in 2026-07-28) · 4 ask the user.
Client MUSTsPKCE (S256) · resource parameter (RFC 8707) = server's canonical URI · validate iss against the recorded issuer (RFC 9207) · Authorization: Bearer on every request, never in the query string.
ScopesRequest the challenge's scope first, else scopes_supported (kept minimal). Step up on 403 insufficient_scope, unioning with scopes already held.
Server MUSTsValidate the audience (token issued for this server) · 401 invalid/expired · 403 insufficient scope · never accept or forward other tokens.
TokensShort-lived access tokens (SHOULD); refresh-token rotation for public clients (MUST); secure storage.

Progressive discovery

  • Principle: smallest set of high-signal tokens; just-in-time loading via identifiers (paths, queries, links); a hybrid of a little up front plus the rest on demand. Context engineering
  • Agent Skills: L1 name + description (~100 tokens per skill, always loaded) → L2 SKILL.md (under 5k tokens, on trigger) → L3 files/scripts (no cost until accessed; script code never enters context). Name ≤ 64 chars, description ≤ 1024 chars and must say what + when. API: runs in the code-execution container, no network. Trusted sources only; audit like software. Agent Skills
  • Tool search tool: regex or BM25; defer_loading: true; returns up to 5 matches by default (Claude can raise limit); up to 10k deferred tools; keep 3–5 most-used tools loaded; preserves the prompt cache; custom search via tool_reference. Use at 10+ tools or more than 10k tokens of definitions; accuracy degrades past 30–50 tools; ~55k → over 85% less. Tool search tool
  • Code execution with MCP: tools as files; filter data in code; PII tokenisation; 150k → 2k tokens (98.7%). Cost: you need a sandbox. Code execution with MCP
  • Programmatic tool calling (GA): allowed_callers on tools; results stay out of context; ~38% fewer input tokens (75-tool benchmark), 20–40% typical at 10–49 tools; no gain for strictly sequential calls; not a security boundary. Programmatic tool calling
