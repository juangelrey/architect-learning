Simplest thing that works; add complexity only when it measurably pays. Building effective agents (Dec 2024; pattern vocabulary still current, tooling section dated)

Building blocks

Augmented LLMLLM + retrieval + tools + memory. The unit everything else is built from.
WorkflowLLMs and tools orchestrated through predefined code paths. Predictable, cheap, testable.
AgentLLM dynamically directs its own process and tool use, in a loop on environment feedback. For unpredictable step counts. Costlier; compounding errors → sandbox, guardrails, stop conditions.

Multi-agent: when (current guidance, Jan 2026)

When to use multi-agent systems

  • Default: single agent; most teams don't need multi-agent. Cost ≈ 3–10× tokens vs single agent.
  • Good fit (3 cases): context pollution degrading performance · parallelisable tasks · specialization improves tool selection or focus.
  • Poor fit: tightly coupled components, sequential phases of the same work, shared context, many inter-agent dependencies, most coding.
  • Decompose by context, not by problem phase. Planner → coder → tester = "telephone game"; one agent owns a feature + its tests.
  • Verification subagent works well; watch for "early victory" (marking pass without real testing).

Delegation & orchestration

  • Delegation spec: objective · output format · tools/sources guidance · clear boundaries. Scale effort to complexity (simple: 1 agent, 3–10 calls). Research system
  • Subagents return condensed summaries (often 1,000–2,000 tokens) → lead context stays clean. Context engineering
  • Managed Agents modes: subagents (delegate + follow up, one level deep) · dynamic workflows (agent writes a program running many agents in phases; default for most multi-agent work) · advisor (one worker consults a stronger model). Cap with a session budget. Multiagent orchestration
  • Long-running agents: initializer session · progress file + git · feature list, one feature at a time · end-to-end self-test. Harnesses (Nov 2025)

Historical data point (June 2025, Claude 4 era)

Multi-agent research system

  • Opus 4 lead + Sonnet 4 subagents beat single-agent Opus 4 by 90.2% (internal research eval).
  • Tokens vs chat: agent ≈ 4× · multi-agent ≈ 15×. Token use explained 80% of BrowseComp variance.

End-to-end checklist

  • Business outcome + metric first (pillar: efficiency, transformation, productivity, cost, performance SLA).
  • Input → processing → output → feedback loop (human edits/outcomes → eval set → iteration).
  • HITL before irreversible/high-impact actions.
